# 全模式链路和公共模块排雷

这轮在 normal 模式修复的基础上，检查并修改了 proxy、outer/inner 反向代理，以及 client、core、server、spring 的公共逻辑。重点是能导致卡顿、断流、串流、内存增长或错误启动的行为，不是仅调整线程数。没有更换现有加密协议或升级整个依赖栈。

## 已修复的问题

### 代理和反向代理

- 代理端按照生效后的配置比较加密类型和密码，避免字段为 null 时误判是否可直接转发。
- 每条反向隧道独立拆包，支持任意位置分开的 8 字节包头、分段包体和粘包。拒绝负数或超过 8 MiB 的声明长度。
- 会话首次建立时选定隧道，后续始终使用同一条；来自其他隧道的相同 tag 不会注入该会话。
- 一条隧道断开只清理其承载的会话。内网端断线会清理目标连接和旧拆包状态，重连后不复用半包。
- 活跃会话不再依赖定时失效的缓存，显式关闭移除回调并释放目标连接，避免过期后丢失数据或资源泄漏。
- 连接和重连使用异步流程；失败后每 3 秒重试，显式 shutdown 后不重连，并释放自有事件循环和 DNS 解析器。
- 没有可用内网端时立即关闭请求连接，避免客户端一直等待。
- 外网端各自持有反向监听器，绑定成功后才接收业务连接；启动失败或退出时释放监听器，不再使用全局单例和无人管理的启动线程。
- 对跨事件循环投递的响应、连接建立前的待发数据和共享隧道输出设置 8 MiB 上限。正常瞬时拥塞允许排队；超限或写失败明确关闭受影响连接，避免无限缓存。极端情况下关闭通知本身也无法发送时会关闭隧道并清理关联会话。
- 普通数据若恰好与旧协议的 4 字节关闭标记相同，发送时拆为两个数据帧，避免误关闭；不修改 tag/length/body 的线路格式。

### 封装、压缩与配置

- FrameWrapper 改为增量状态机。修复续帧分片时补零、跨次读取丢失已收数据，以及不完整输入返回 null 的问题。
- 压缩支持空输入；截断、无进展或非法压缩包立即报错，不再空转。Deflater/Inflater 每次使用后释放，解压结果上限为 8 MiB。
- 检查 padding 长度和帧头边界，避免畸形输入触发越界或失控分配。
- 支持绝对配置路径和 UTF-8 文件，读取时释放文件资源。
- 配置不存在、不可读、为空、模式或端口不合法时停止启动并报错，不再悄悄生成或采用默认配置。有效配置中的旧默认字段值仍保留兼容性。
- 启动日志及配置读取示例不再打印密码。

### 公共服务、HTTP 与 WebSocket

- 服务 shutdown 同时关闭监听连接、已接受连接和事件循环；启动失败也清理资源。关闭后加入的连接立即关闭，覆盖 bind/shutdown 竞态。
- Spring 服务退出或关闭后移除服务注册，允许同名服务再次启动。
- TCP 异常仅通过 channelInactive 通知一次关闭；旧连接的关闭事件不再覆盖新连接状态。
- HTTP 以 LastHttpContent 为请求结束边界，修复按一次 socket 读取完成就派发、FullHttpRequest 漏正文、拆开的 UTF-8 字符出错等问题。
- WebSocket 保留独立消息边界，支持文本续帧和中间插入的 Ping/Pong；控制帧不派发业务请求，Ping 立即回复。
- WebSocket 升级使用完整请求快照，避免等待已被消费的 HTTP 尾部，也支持业务处理稍后才返回升级响应。
- HTTP 正文与完整 WebSocket 文本消息限制为 1 MiB。此限制不影响 VPN 转发的总文件大小。
- 修复第一条响应头未添加、空正文不拷贝响应头、Connection: close 未实际关闭、属性删除用错键的问题。客户端 IP 使用数值地址，避免反向 DNS 查询。

## 验证记录

2026-09-25 本地全模块构建成功，36 项 JUnit 测试全部通过（原有 11 项，新增 25 项）。测试在 JBR 25 上以 Java 8 release 编译；未另外运行 Java 8 虚拟机。

新增覆盖包含：

- 反向协议所有切分位置、非法长度、双隧道隔离、错误隧道注入、单隧道断开和无可用内网端。
- 帧续包、600,000 字节随机数据的压缩及两种 padding 分片恢复；7 种现有 cipher 的逐字节 IV/正文恢复。
- 真实 TCP proxy 同配置直转和 AES 配置转换、三种帧封装；outer/inner 两条 cipher 路径及压缩路径。每条测试链路传输 1 MiB，检查目标主动问候和客户端断开清理。
- 反向端断线重连、重复 shutdown、关闭后不重连、端口冲突和启动关闭竞态。
- HTTP 半包、完整请求、流水请求、UTF-8、超限；WebSocket 消息边界、续帧、Ping 和延迟完成握手。
- 慢输出达到队列上限时拒绝新增数据，已完成写释放额度；旧关闭标记与普通数据冲突的兼容转义。

打包后另以独立 `java -jar` 进程验证：

- normal + proxy：绝对配置路径，4 路并发、每路 1 MiB 双向校验，断开后目标连接清理。
- outer + inner：同样的 4 路并发传输，结束 inner 进程后旧业务连接关闭，重启 inner 后新业务恢复并再次通过并发传输。
- 单独 normal：64 KiB 数据、仅地址头触发服务端问候、断开清理。
- fat JAR 内 AES 编解码自检。

以上为本机回环功能和并发测试，不是公网吞吐/延迟基准，也不代表长时间丢包环境下已经完成压力测试。

## 使用与兼容性

打包：`mvn package`。输出为 `vpn/target/panama.jar`。

启动：`java -jar panama.jar /absolute/path/panama.config`。未传参数时读取进程当前工作目录中的 `panama.config`，不是自动查找 JAR 所在目录。

建议同时更新 outer 和 inner，以获得两端的拆包、队列和关闭标记修复。已有配置格式保持不变。帧/解压包及待发队列有上述限制；超过限制时会明确终止连接，不会静默丢弃部分数据继续转发。嵌入式调用的 `createRedirect2ReverseShadowSocksProxy` 现在需要显式传入所属 ReverseCoreServer。

## 仍需单独处理的边界

- 反向隧道仍沿用旧的无身份认证连接协议，本轮没有新增隧道认证或 TLS。不要把本次逻辑修复当作协议安全升级。
- 现有 `encrypt` 使用 CFB/OFB；`raw`、`compress`、`zero-padding`、`random-padding` 单独选择时不提供加密。密码字段缺省时的旧默认值仍存在，应显式配置实际密码。
- Netty 4.1.31.Final、Fastjson 1.2.58、Log4j 1.2.17 等依赖版本未在本轮升级；没有声称已完成依赖漏洞清零。依赖迁移需要另一组兼容性验证。
- 复用隧道没有逐会话流控协议；超出有界队列的慢连接会被关闭。未增加 UDP 支持、线路选择、心跳协议或公网测速能力。
